# PaperFig 架构设计 — 结构定义

> 历史归档（2026-10-22）：本文记录早期 HTML/Vega 方案，其中的旧模块路径与阶段状态仅供回顾；相关渲染器已移除，不能作为当前实现或扩展指南。当前说明见 [Matplotlib 后端](matplotlib-backend.md)、[开发指南](dev-notes.md)和 [CSV 入口](simple-api.md)。

> **核心设计原则**（一句定论）：
>
> **Chart 决定"画什么"，Compute 决定"怎么算"，Layout 决定"放哪里"，Theme 决定"长什么样"。**
>
> 四条边界永不互侵 → 永不退化为 matplotlib 参数堆积。

---

## 一、为什么不是 "更好的 matplotlib"

matplotlib/seaborn 的根本问题不是功能不足，而是**职责混合**：

```python
# matplotlib 一行代码里混合了 4 层逻辑
plt.figure(figsize=(8,4))   # 排版逻辑
plt.bar(x, y)               # 图形逻辑
plt.legend(bbox_to_anchor=...) # 样式逻辑
data = mean/std             # 数据逻辑（隐式，散布在脚本各处）
```

| 层 | matplotlib | PaperFig |
|----|-----------|----------|
| 数据计算 | 散布在脚本各处 | `compute/` — 独立模块 |
| 图形逻辑 | 与渲染混合 | `charts/` — 纯定义 |
| 排版布局 | 手动 plt.subplot + bbox | `layout/` — 声明式 |
| 样式主题 | 逐行手调 font/color/dpi | `themes/` — 一键切换 |

→ 换一次论文（CVPR → ACL → IEEE），matplotlib 要全量重调；PaperFig 只改 `theme="acl"`。

│   │   ├── figure.py            #   顶层 API：Figure() 入口
│   │   ├── spec.py              #   FigureSpec 内部统一中间表示（AST 角色）

│   ├── data/                    # CSV → 数据对象

│   │
│   ├── themes/                  # 主题配置（JSON 主题文件）

## 三、各模块职责速查表

| 模块 | 负责 | **不负责** |
|------|------|------------|
| `data/` | CSV → DataFrame，列类型识别+校验 | 统计计算、绘图 |
| `compute/` | groupby/mean/std/percentile | 颜色、字体、布局 |
| `core/` | 用户配置 → 统一 FigureSpec (AST) | 渲染 |
| `layout/` | 子图位置/尺寸/间距/字号推导 | 数据、样式 |
| `charts/` | 图表需要的字段定义、计算需求声明 | set_color/set_font 等渲染 |
| `renderer/` | FigureSpec → Altair → SVG/PDF/PNG | 数据计算 |
| `themes/` | 色板/字号/网格/legend 样式 (JSON) | 数据、图表类型 |
| `utils/` | 调色板、颜色工具 | 业务逻辑 |

## 四、数据流（完整链路）

```
results.csv
    │
    ▼
┌──────────────┐
│  data/        │  loader.py → schema.py → transform.py
│  DataFrame    │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  compute/     │  aggregation + statistics + preprocess
│  聚合数据     │  (箱线图例外：由 Altair 运行时计算)
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  core/spec.py │  用户映射 → FigureSpec (内部 AST)
│  FigureSpec   │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  layout/      │  manager → grid → sizing
│  位置/尺寸    │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│  renderer/    │  vega.py → Altair → SVG/PDF/PNG
│  SVG / PDF    │  legend.py (手绘 marks legend)
└──────────────┘
```

中间表示 `FigureSpec` 是整个系统解耦的关键——上游模块只产出 Spec，下游模块只消费 Spec。

## 六、目标 API 形态

```python
from data_visuals.core import Figure

fig = Figure(data=df, rows=2, cols=2, title="Main Title")

fig[0, 0].bar(x="method", y="accuracy")
fig[0, 1].line(x="epoch", y="loss")
fig[1, 0].box(x="method", y="score")

fig.render("output.svg")
```

> 无 `plt.subplots_adjust()` / `bbox_to_anchor()` / `tight_layout()` — 全部由 layout 和 theme 自动处理。

## 八、Theme 文件示例

```json
// themes/general.json
{
    "font_family": "Times New Roman",
    "color": {
        "categorical": ["#4c72b0", "#dd8452", "#55a868", "#c44e52", ...]
    },
    "axis": {
        "grid": true,
        "grid_color": "#c0c0c0",
        "grid_opacity": 0.6,
        "tick_count": 5,
        "domain_padding": 0.2
    },
    "legend": {
        "symbol_size": 80,
        "symbol_stroke_width": 1.5,
        "padding": 8
    }
}
```

> 主题系统不按投稿会议分类，而是定义常用色板与视觉风格。
> 新增风格只需新增或修改一个 JSON 文件，零代码改动。

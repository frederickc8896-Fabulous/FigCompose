# PaperFig — 规则驱动的论文级数据可视化引擎

> 历史归档（2026-10-22）：本文记录早期 HTML/Vega 方案，其中的旧模块路径与阶段状态仅供回顾；相关渲染器已移除，不能作为当前实现或扩展指南。当前说明见 [Matplotlib 后端](matplotlib-backend.md)、[开发指南](dev-notes.md)和 [CSV 入口](simple-api.md)。

> **定位**: A reproducible, publication-quality visualization engine for researchers.
>
> **核心理念**: 不是 AI 画图，而是通过规则 DSL 消除科研绘图中大量重复性的视觉配置工作。

---

## 一、项目总览

```
CSV 数据 → 用户最小配置 → 规则引擎 → 统一风格论文 Figure → SVG/PDF
```

### 设计原则

| 原则 | 说明 |
|------|------|
| **规则驱动** | 完全 deterministic，可复现，review-friendly |
| **弱耦合** | 数据预处理、统计计算、Layout、渲染四个模块完全解耦 |
| **极简配置** | 用户只需声明 x/y/layout，无需调 figsize/dpi/font/color |
| **论文优先** | 内置固定审美规范（Helvetica、minimal axis、无网格、2pt 线宽） |

### 明确不做的事

- ❌ JSON schema / semantic understanding
- ❌ LLM 智能推断
- ❌ 复杂的交互式图表
- ❌ GUI 拖拽配置

## 二、CSV 数据规范

### 约束条件

1. **第一行必须是 header**（即列名变量名）
2. **每列一个变量**
3. 工具自动识别列类型：
   - `categorical` — 分类变量
   - `numerical` — 数值变量

### 示例

```csv
method,dataset,accuracy,std
A,ETTh1,0.81,0.02
B,ETTh1,0.84,0.01
Ours,ETTh1,0.89,0.01
```

```text
method       → categorical
dataset      → categorical
accuracy     → numerical
std          → numerical
```

## 三、Layout Engine（布局引擎）⭐ 核心模块

> 不要从 chart type 开始思考，应该从 Layout 开始。这是整个工具最重要的架构决策。

### 层级模型

```
Figure
 └── Layout
      └── Chart(s)
           └── Data Mapping (x / y / group)
```

### Layout A：单图 (Single)

```
+-------------------+
|                   |
|      Chart        |
|                   |
+-------------------+
```

### Layout B：并置子图 (Grid)

```
+-----------+-----------+
|  Chart 1  |  Chart 2  |
+-----------+-----------+
```

### Layout C：混合布局 (Hybrid)

```
+-------------------------+
|       Main Chart        |
+-----------+-------------+
|  Chart 1  |   Chart 2   |
+-----------+-------------+
```

> 设计理念借鉴 LaTeX 的 `figure` / `subfigure` 环境，本质上是 **"LaTeX figure environment for data visualization"**。

### 用户声明 Layout 的方式

```python
layout = [
    ["bar", "line"],   # 第一行：两个并置子图
    ["box"]            # 第二行：一个单图（跨全宽）
]
```

## 五、Aggregation Engine（统计计算层） ✅ 已落地

> 只做纯统计计算，不做推断或建模。

### 内置聚合算子

| 算子 | 用途 |
|------|------|
| `mean` | 均值 |
| `std` | 标准差 |
| `median` | 中位数 |
| `percentile` | 百分位数（Q1/Q3） |
| `count` | 计数 |

### 按图表类型触发计算

| 图表类型 | 触发计算 |
|----------|----------|
| **bar** | `groupby(x) → mean() / std()` (由 `compute/aggregation.py` 执行) |
| **box plot** | `compute/statistics.py` 产出箱线摘要与 outlier，renderer 优先消费预计算结果 |
| **line** | 无需聚合，直接用原始值 |
| **scatter** | 基础散点无需聚合；`trend=True` 时由 `compute/statistics.py` 预计算趋势线 |
| **heatmap** | `groupby(x, y) → mean()` 或 `count()` |
| **histogram** | 基础直方图无预聚合；`density=True` 时 KDE 由 `compute/statistics.py` 预计算 |
| **confusion** | `(x, y) → count` 由 `compute/aggregation.py` 执行；补齐缺失组合与 `normalize=True` 由 `compute/preprocess.py` 执行 |

### 2026-07-08 架构审计结论

当前代码库中，**所有图表已经共用统一的 orchestration + layout 管线**：

```text
Figure.build()
    -> ChartSpec.compute_requirements()
    -> aggregate() 或原始数据直通
    -> build_layout()
    -> detect_shared_axes()
    -> FigureSpec
    -> renderer/vega.py 分发到各 chart builder
```

当前代码库中，**数据处理已经收敛到 `Figure.build()` 主链 + `compute/` 层**；renderer 只消费 `computed_data` / `derived_data`，并保留少量兼容性 fallback：

| 图表类型 | 共用统一 layout 管线 | 共用统一 Figure.build 主链 | 数据处理是否完全在 compute/ | 当前状态 |
|----------|----------------------|----------------------------|-----------------------------|----------|
| `bar` | ✅ | ✅ | ✅ | 基础聚合 + 百分比预处理 + overall mean 已进入 compute 主链 |
| `line` | ✅ | ✅ | ✅ | 直接使用原始数据，无额外统计 |
| `scatter` | ✅ | ✅ | ✅ | 基础散点直通原始数据；`trend=True` 的 LOWESS 已由 compute 预计算 |
| `box` | ✅ | ✅ | ✅ | 由 `compute/statistics.py` 产出 `box_summary` / `box_outliers`，renderer 优先消费预计算载荷 |
| `heatmap` | ✅ | ✅ | ✅ | 聚合值由 compute 层准备，renderer 只负责映射 |
| `histogram` | ✅ | ✅ | ✅ | 直方图直通原始数据；密度曲线由 compute 预计算，renderer 只做绘制 |
| `confusion` | ✅ | ✅ | ✅ | 计数聚合、补齐组合、normalize 均已在 compute / preprocess 主链中完成 |

**结论**：

- `layout` 主链：✅ 已统一
- `FigureSpec` 中间表示：✅ 已统一
- `compute` 作为所有图的数据处理唯一入口：✅ 已成立
- 单一职责原则：✅ 主链已成立；renderer 仅保留兼容性 fallback，不再承担统计主职责

## 六、Legend 设计 ✅ 已完成

### 共享 Legend（默认）

当多个子图使用同一 `group` 列时，自动生成全图唯一的共享 legend，
放在主标题下方，由 `renderer/legend.py` 手绘 marks 实现像素级居中。

### 非共享 Legend（per-cell）

当某个子图的 `group` 列与共享 legend 不同时，
该 cell 自动获得独立的 marks-based legend，放在 cell 标题下方。

### 自定义映射（可选）

允许用户通过 labels 覆盖显示名：

```python
fig[r, c].bar(x="method", y="accuracy", group="model",
              labels={"Ours": "Our Framework"})
  GPT: "GPT-4o"
```

## 七、技术架构

### 7.1 整体数据流

```
CSV 文件
    │
    ▼
┌─────────────────┐
│  Column Parser   │  ← 读取 header，自动识别 categorical / numerical
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  User Mapping    │  ← 用户声明 x / y / layout / group
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Aggregation      │  ← mean / std / median / percentile / count
│ Engine           │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ Template         │  ← Vega-Lite JSON 模板渲染
│ Renderer         │
└────────┬────────┘
         │
         ▼
    SVG / PDF
```

### 7.2 技术选型

| 层 | 技术 | 职责 |
|----|------|------|
| **Backend** | Python + pandas | CSV 解析、统计聚合、配置管理 |
| **Renderer** | Vega-Lite (HTML/JS) | 声明式可视化渲染，config → visualization |
| **Export** | Vega 导出 | SVG / PDF 输出 |

### 7.3 推荐项目结构

```
paperfig/
├── python/
│   ├── parser.py          # CSV 解析 + 列类型识别
│   ├── statistics.py      # 聚合引擎
│   └── config.py          # 配置管理（Theme / Layout）
├── templates/
│   ├── bar.json           # Vega-Lite 柱状图模板
│   ├── line.json          # Vega-Lite 折线图模板
│   ├── box.json           # Vega-Lite 箱线图模板
│   ├── scatter.json       # Vega-Lite 散点图模板
│   └── heatmap.json       # Vega-Lite 热力图模板
└── renderer/
    └── vega.js            # 渲染入口
```

## 十、为什么这条路比"AI 智能画图"更容易成功

| 维度 | LLM 画图 | PaperFig（规则引擎） |
|------|----------|---------------------|
| **稳定性** | ❌ 不稳定，输出不可控 | ✅ deterministic |
| **可复现性** | ❌ 每次结果可能不同 | ✅ 完全可复现 |
| **审稿友好** | ❌ 难追溯生成逻辑 | ✅ 规则透明，可审查 |
| **论文适配** | ❌ 审美不可控 | ✅ 内置论文规范 |
| **学习成本** | ⚠️ prompt 调试复杂 | ✅ 声明式，类似 LaTeX |

**论文社区真正需要的是这个，而不是又一个 AI wrapper。**

### 12.5 已验证的架构边界

```

> 因此，**依赖边界与职责边界都已经在主链上落地**。
```
